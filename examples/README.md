# Example configuration

These examples contain no passwords, master keys or subscriber records. Use
`tvcas init` for a new installation; it generates fresh private values locally.
For existing programmed cards, import their original settings instead.

## Local connection layout

| Connection | Direction | Example |
|---|---|---|
| Web UI | Browser → TVCAS | `127.0.0.1:8091` |
| ECMG | Scrambler → TVCAS | `127.0.0.1:42000` |
| EMMG | TVCAS → scrambler/MUX | `127.0.0.1:41000` |

The EMMG **host** is the destination MUX address, not the TVCAS listening address.
The scrambler must listen there. If components run on different machines, replace
loopback with the appropriate reachable addresses and permit those TCP ports.

One ECMG can serve multiple scrambler peers. An EMMG connects to one MUX endpoint;
use one entry for a shared MUX/fan-out endpoint if your scrambler system provides
one. This server does not include the headend's EMM fan-out helper. Standalone
outputs still need their EMM sections and CAT supplied by the scrambler/MUX.

## Global settings

In **Настройки** (Settings):

| Field | New-install example | Meaning |
|---|---|---|
| CAID / `ident` | `0B00` | Four hexadecimal characters |
| CAS name / `trademark` | `Example CAS` | Card display label |
| EMM offset / `zone` | `+0000` | Fixed UTC offset, not automatic DST |
| CONFIG timezone / `php_timezone` | `UTC` | Date packing for uploader CONFIG |
| ECM key | Generated by `init` | 32 bytes / 64 hex characters; keep private |
| Billing API key | Generated by `init` | Private credential for the legacy API |

Blank key/password fields preserve the existing value. A newly created ECMG gets
its own copy of the global ECM key. Changing the global key later does **not**
rewrite existing generators or programmed cards. Preserve key text case when
migrating; the card CONFIG includes a hash of the hexadecimal text.

## Create generator records

With the offline web server running, use **ECMG → + Добави** and
**EMMG → + Добави**, or POST the provided JSON examples. Run these commands from
the checkout root. Curl prompts for the admin password; no password is placed in
the command or file:

```sh
curl --fail --user admin --header 'Content-Type: application/json' \
  --data-binary @examples/ecmg.json http://127.0.0.1:8091/api/ecmg
curl --fail --user admin --header 'Content-Type: application/json' \
  --data-binary @examples/emmg.json http://127.0.0.1:8091/api/emmg
```

Each POST creates another record; do not repeat it to update an existing entry.
The responses redact keys. Both records start disabled. Enable them in their web
lists and follow the global activation steps in the main README.

`ecmg.json` uses `host: 2130706433`, the PHP-compatible unsigned integer for
`127.0.0.1`. The ECMG form/API currently stores IPv4 as an integer (`0` means all
IPv4 interfaces). EMMG uses an ordinary host string. Convert another ECMG address:

```sh
python -c 'import ipaddress; print(int(ipaddress.IPv4Address("192.0.2.10")))'
```

The `192.0.2.10` address above is documentation-only; replace it with your bind IP.

### ECMG profile

The examples use section mode `packet_mode=0`, two 8-byte DVB-CSA words per
request, `lead_CW=1`, ECM repetition 200 ms and `min_cp_duration=100` (units of
100 ms, therefore 10 seconds). Delay and transition fields are milliseconds.
An 11-second crypto period is a suitable example for this profile. The scrambler
selects the actual period; TVCAS advertises constraints. `network_id` is retained
TVCAS metadata, not a DVB NIT/TS network generator.

The original `ecm_time1`, `ecm_time2` and `ecm_block_time` fields are retained for
round trips; they do not control the Python ECMG scheduling.

Advanced `cw_order` and `csa_entropy_reduction` are database profile fields,
currently not editable in the generic web form or JSON CRUD API. For the native
[DVB Scrambler](https://github.com/smdbg/dvb-scrambler), explicitly select `cp`
ordering with entropy reduction off. With TVCAS **stopped**, and using the actual
ECMG ID returned when creating the record (1 below is only an example):

```sh
python - "$HOME/.local/share/tvcas/tvcas.sqlite" 1 <<'PY'
import sys
from tvcas.__main__ import database_lock, existing_database
from tvcas.storage import Store
path = existing_database(sys.argv[1])
with database_lock(path):
    store = Store(path)
    row_id = int(sys.argv[2])
    if store.get_row('ecmg', row_id) is None:
        raise SystemExit('ECMG ID does not exist')
    store.save_row('ecmg', {'cw_order': 'cp', 'csa_entropy_reduction': False}, row_id)
PY
```

Imported records default to `legacy` ordering. Do not change a working legacy
profile blindly. Older TSDuck versions may require `csa_entropy_reduction=True`;
see [compatibility](../docs/compatibility.md). This affects only CW normalization,
not the ECM master key.

### EMMG profile

The example uses SimulCrypt v2, section mode 0, `client_id=184549377`
(`0x0B000001`), network metadata 1 and a requested allocation of 64 kbit/s.
The MUX decides the actual allocation. Allocation zero pauses EMM data; keepalives
continue. `repetition=60` and `reload_sec=300` are seconds. Card edits request an
immediate queue refresh; expired cards are excluded. `period`, `period_messages`
and `uid` are retained legacy fields, not separate timers in this implementation.

For `bs-scrambler`, match `--super-cas-id 0x0B000001`, configure its ECMG as
`127.0.0.1:42000` and its EMM listener as `127.0.0.1:41000`. Choose unique ECM/EMM
PIDs in the scrambler and downstream transport. CAS does not allocate MPEG PIDs.

## Cards

Create cards in **Смарткарти → + Добави**. Set your actual serial number, name,
access mask and UTC validity. For a service using access criteria `0x1`, a card
mask `00000001` grants that bit. Leave the individual key blank for a new locally
generated 16-byte key. Use the original card key when migrating a programmed card.

Only the administrator can download the 90-byte `CONFIG.bin` used by the original
card uploader. It contains the ECM master key and the individual card key.
It is not firmware and is not a public example file.
